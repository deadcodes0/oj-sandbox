## 二、架构全景图（先看地图，再看代码）

学习微服务最大的坑是"陷入细节，看不到全貌"。请先在脑海里建立下面这张图：

```
                          客户端请求
                              │
                              ▼
                    ┌─────────────────────┐
                    │  oj-backend-gateway │  端口 8101
                    │   (路由 + 鉴权过滤)  │
                    └──────────┬──────────┘
                               │ 按 Path 路由
       ┌───────────────┬───────┴────────┬───────────────┐
       ▼               ▼                ▼               ▼
  user-service   question-service   judge-service   rag-service
   (8102)          (8103)             (8104)         (8105)
       │               │                │               │
       │   Feign 调用   │                │               │
       │◄──────────────┘                │               │
       │               │  RabbitMQ      │               │
       │               │───────────────►│               │
       │               │   异步判题      │               │
       │               │                │   调用沙箱     │
       └───────────────┴────────────────┴───────────────┘
                 ▲                          ▲
                 │                          │
            MySQL + Redis              Nacos (注册中心)
```

**核心协作关系**：

- 客户端 → Gateway → 按路径路由到对应业务服务
- `judge-service` 通过 Feign 调用 `question-service` 的内部接口获取题目信息
- `question-service` 通过 RabbitMQ 把判题任务异步推送给 `judge-service`
- 所有服务启动时都注册到 Nacos，相互通过服务名发现

## 三、分阶段学习路线

### 第①步：服务注册与发现（Nacos）

**学习重点**：服务如何"上线"，如何被其他服务找到。

**看什么代码**：

1. 启动类 [OjBackendUserServiceApplication.java](file:///d:/Coding/oj--microservice-main/oj-backend-user-service/src/main/java/com/oj/ojbackenduserservice/OjBackendUserServiceApplication.java)
   - 关键注解：`@EnableDiscoveryClient`
2. 配置文件 `oj-backend-user-service/src/main/resources/application.yml`
   ```yaml
   spring:
     cloud:
       nacos:
         discovery:
           server-addr: 127.0.0.1:8848
   ```

**验证动作**：

- 启动 Nacos，访问 http://localhost:8848/nacos （账号密码 nacos/nacos）
- 启动 user-service，在 Nacos 控制台"服务列表"中应能看到 `oj-backend-user-service`

**思考题**：如果 Nacos 挂了，服务还能调用吗？（提示：客户端缓存机制）

---

### 第②步：远程调用（OpenFeign + 负载均衡）

**学习重点**：服务之间如何像调本地方法一样发起 HTTP 调用。

**看什么代码**：

1. Feign 接口定义 [QuestionFeignClient.java](file:///d:/Coding/oj--microservice-main/oj-backend-service-client/src/main/java/com/oj/ojbackendserviceclient/service/QuestionFeignClient.java)
   ```java
   @FeignClient(name = "oj-backend-question-service", path = "/api/question/inner")
   public interface QuestionFeignClient {
       @GetMapping("/get/id")
       Question getQuestionById(@RequestParam("questionId") long questionId);
   }
   ```
2. 启动类上的 `@EnableFeignClients(basePackages = {"com.oj.ojbackendserviceclient.service"})`
3. 被调用方：`oj-backend-question-service` 的 `controller/inner/QuestionInnerController.java`

**做什么**：

- 理解 `name` 属性对应 Nacos 中注册的服务名，Feign 会通过负载均衡选一个实例发起请求
- 理解 `path` 与 Controller 上的 `@RequestMapping` 如何拼接成完整 URL

**断点调试建议**：

- 在 `QuestionFeignClient.getQuestionById` 调用处打断点
- Step Into 会进入 Feign 生成的代理对象，观察实际发起的 HTTP 请求

**思考题**：为什么要把内部接口放在 `inner` 包下？（提示：网关过滤）

---

### 第③步：网关（Spring Cloud Gateway）

**学习重点**：统一入口、路由转发、全局过滤器。

**看什么代码**：

1. 路由配置 `oj-backend-gateway/src/main/resources/application.yml`
   ```yaml
   spring:
     cloud:
       gateway:
         routes:
           - id: oj-backend-user-service
             uri: lb://oj-backend-user-service
             predicates:
               - Path=/api/user/**
   ```
2. 全局过滤器 [GlobalAuthFilter.java](file:///d:/Coding/oj--microservice-main/oj-backend-gateway/src/main/java/com/oj/ojbackendgateway/filter/GlobalAuthFilter.java)
   - 关键点：实现 `GlobalFilter, Ordered` 接口
   - 逻辑：拦截 `/**/inner/**` 路径，返回 403

**做什么**：

- 跟踪一个请求 `/api/user/login`：
  1. 网关收到请求
  2. `GlobalAuthFilter` 校验路径
  3. 路由断言 `Path=/api/user/**` 匹配
  4. 通过 `lb://` 前缀负载均衡到 user-service 实例
  5. 转发请求到 `http://user-service-ip:8102/api/user/login`

**验证动作**：

- 直接访问 `http://localhost:8101/api/question/inner/get/id` 应返回 403
- 访问 `http://localhost:8101/api/user/...` 正常路由

**思考题**：`lb://` 是怎么解析成具体 IP:端口的？（提示：LoadBalancer + Nacos）

---

### 第④步：异步消息（RabbitMQ）

**学习重点**：用消息队列解耦耗时操作（判题）。

**看什么代码**：

1. 队列初始化 [InitRabbitMq.java](file:///d:/Coding/oj--microservice-main/oj-backend-judge-service/src/main/java/com/oj/ojbackendjudgeservice/rabbitmq/InitRabbitMq.java)
   - 交换机：`code_exchange`（direct 类型）
   - 队列：`code_queue`
   - 路由键：`my_routingKey`
2. 消息生产者：`oj-backend-question-service` 的 `rabbitmq/MyMessageProducer.java`
3. 消息消费者 [MyMessageConsumer.java](file:///d:/Coding/oj--microservice-main/oj-backend-judge-service/src/main/java/com/oj/ojbackendjudgeservice/rabbitmq/MyMessageConsumer.java)
   ```java
   @RabbitListener(queues = {"code_queue"}, ackMode = "MANUAL")
   public void receiveMessage(String message, Channel channel, @Header(AmqpHeaders.DELIVERY_TAG) long deliveryTag) {
       long questionSubmitId = Long.parseLong(message);
       try {
           judgeService.doJudge(questionSubmitId);
           channel.basicAck(deliveryTag, false);   // 成功确认
       } catch (Exception e) {
           channel.basicNack(deliveryTag, false, false);  // 失败丢弃
       }
   }
   ```

**做什么**：

- 理解完整异步判题流程：
  ```
  用户提交代码 → question-service 保存记录 → 发送 submitId 到 MQ
                                                      ↓
  judge-service 消费消息 → 调用沙箱执行 → 保存判题结果
  ```

**验证动作**：

- 访问 RabbitMQ 管理台 http://localhost:15672 （guest/guest）
- 提交一次代码，观察 `code_queue` 的消息进出情况

**思考题**：为什么用 `ackMode = "MANUAL"` 而不是自动确认？（提示：消息可靠性）

---

### 第⑤步：公共模块与统一规范

**学习重点**：微服务如何抽取公共能力，保证一致性。

**看什么代码**：

1. 统一响应：`oj-backend-common/common/BaseResponse.java`、`ResultUtils.java`
2. 全局异常：`oj-backend-common/exception/GlobalExceptionHandler.java`
3. 权限注解：`oj-backend-common/annotation/AuthCheck.java`
4. 业务异常：`oj-backend-common/exception/BusinessException.java`
5. 错误码：`oj-backend-common/common/ErrorCode.java`

**做什么**：

- 理解为什么所有服务都依赖 `oj-backend-common` 和 `oj-backend-model`
- 学习"统一返回格式 + 全局异常处理"的经典套路

**思考题**：为什么 `oj-backend-model` 要单独抽成模块？（提示：Feign 接口共享 DTO）

### 第⑥步：补充中间件（Redis、RAG 扩展）

**Redis 相关**：

- 配置：`spring.session.store-type: redis`（分布式 Session）
- 作用：所有服务共享登录态，网关转发后不会丢失会话

**RAG 服务（进阶）**：

- `oj-backend-rag-service` 整合 Qdrant 向量库 + LLM
- 排除了 JDBC 自动配置（不连 MySQL）
- 可作为学习"AI + 微服务"的扩展材料

## 六、学习建议总结

1. **先架构后细节**：不要一上来就啃配置文件，先建立全局视图。
2. **每次只聚焦一个组件**：结合官方文档理解配置项作用，避免信息过载。
3. **动手改 + 断点调**：看十遍不如改一遍，改一遍不如调一遍。
4. **带着问题学**：每看一段代码，先问"它解决什么问题"，再看"它怎么解决"。
5. **卡住就追问**：组件之间是有关联的，某个点卡住往往是因为前置概念没理清。
